# Local-only Polar cutover

- Migration: `20261020133500_polar_org_cutover.sql`; shared with fc-landing. Apply it ONCE before deploying either webhook. Adds service-role-only `billing_customers`, `polar_subscription_state`, `polar_webhook_events` and `apply_polar_subscription_event` RPC. Bootstraps one latest apparently-paid historical subscription per user and customers as old-org records; excludes immediate canceled/revoked histories. Leaves existing subscriptions reader schema unchanged.
- RPC parameters: `p_org_id uuid, p_event_id text, p_event_at timestamptz, p_user_id uuid (nullable), p_customer_id text, p_subscription jsonb, p_plan text (nullable)`. Returns `applied`, `duplicate`, or `stale`. All changes roll back together on error. Customer mapping is one customer per org per user; conflicts require explicit operator review, never reassignment.
- New checkouts: six monthly regional `POLAR_{PRO|PRO_PLUS}_PRODUCT_ID_{US|KR|JP}` keys only. Yearly/common/enterprise checkout is disabled. Both checkout `metadata.user_id` and `external_customer_id` carry the authenticated user UUID.
- Old webhook retains `POLAR_WEBHOOK_SECRET` and common `POLAR_PRO_PRODUCT_ID`, `POLAR_PRO_PLUS_PRODUCT_ID`, `POLAR_ENTERPRISE_PRODUCT_ID`. Twelve old regional products use `POLAR_LEGACY_{PRO|PRO_PLUS}_PRODUCT_ID_{US|KR|JP}[_YEARLY]`. Unknown product never grants a plan.
- Set `POLAR_WEBHOOK_SECRET_NEW` ONLY if a real new-org endpoint targets this Edge function. Do not copy a website endpoint secret: signatures are endpoint-specific. Do not replace the old secret. `POLAR_ACCESS_TOKEN` must belong to the new org before enabling new checkout IDs.
- Standard Webhooks checks `webhook-id`, `webhook-timestamp`, `webhook-signature`, decoded secret, exact raw body and 5-minute tolerance. Legacy raw `x-webhook-signature` HMAC remains supported. Legacy payloads must have event `timestamp`; Standard payloads may fall back to signed delivery timestamp. Prefer payload timestamp for true subscription ordering.
- Keep `polar-webhook` deployed with JWT verification disabled. Checkout requires JWT. Enable created/active/updated/canceled/revoked/uncanceled subscription events. Scheduled cancellation retains entitlement until period end; revoke removes it immediately. Timely Polar revoke at period end is required to update profile materialization if no further webhook arrives. No local timer/cron added.
- Existing rows bootstrap one latest eligible historical subscription using current profile plan because historical product catalogs are not in DB. Audit historical mixed-plan and overlapping subscriptions before rollout. Edge rejects unknown nonterminal products; explicit terminal revocation may use null plan and cannot grant. Manual tester/team plans are preserved; non-entitling events do not downgrade trial/free.
- Subscription-created and order-paid Slack notices use the shared durable service-only notification outbox. Semantic event key is `subscription.created:<subscription-id>` or `order.paid:<order-id>`, independent of endpoint delivery ID. Claim grants a fenced 60-second lease; send the stored canonical payload, finish true only after Slack success. If Slack is intentionally unconfigured, Edge skips before any enqueue/claim and acknowledges normal billing. Configured Slack delivery failure releases the lease and remains retryable. Already-sent returns success without sending. Recovery uses Polar retries, not an added cron.
- RPC: `claim_polar_notification(p_org_id uuid,p_event_id text,p_payload jsonb) returns jsonb {status: claimed|busy|sent,lease_id: uuid|null,payload:jsonb}`; `finish_polar_notification(p_org_id uuid,p_event_id text,p_lease_id uuid,p_sent boolean) returns boolean` (false for stale/expired owner). Both SECURITY INVOKER with service_role-only EXECUTE/table grants. First durable payload wins across destinations.
- Lease fencing prevents simultaneous duplicate dispatch. A crash after Slack accepts but before successful finish can still cause a duplicate on retry: Slack webhooks offer no transactional idempotency. No claim of exactly-once external delivery.
- Canonical revoked/ended states project to legacy `subscriptions.status=canceled`, matching the production status CHECK. The canonical table retains terminal status for entitlement decisions; `trial_end` is preserved.
- CI workflow `.github/workflows/polar-billing-tests.yml` fails on unit, PostgreSQL fixture, or Edge typecheck errors. Its PostgreSQL fixture runs in one PGlite connection: simultaneous calls exercise serialized contention, not independent-connection MVCC stress. Full local Supabase replay remains mandatory.
- WARNING: existing Edge deployment workflow selects ALL functions when `_shared` changes. Do not deploy unrelated functions blindly; explicitly review/limit rollout to billing consumers using the existing deployment controls.

PGlite is installed at pinned `0.3.14` plus TypeScript `5.9.3` into `$RUNNER_TEMP/polar-billing-tests` using repository-pinned pnpm `11.3.0` with lifecycle scripts disabled; repository dependencies/credentials are unchanged. Both workflows compile `supabase/tests/polar-database-types.ts`, which asserts public-schema placement, GraphQL exclusion and billing foreign keys. The historical misplacement fails the negative-control compilation.

Missing function/schema-cache errors, anonymous success, generic auth failures, malformed responses, missing configuration, and transport failures block deployment. The test supplies deliberately invalid business data with every named argument, never service-role credentials. It logs function names and generic outcomes only. The live readiness check was NOT run during local implementation.
