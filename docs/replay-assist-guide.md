# Replay Assist 운영 가이드

레퍼런스 배치의 화력 명령을 이번 배치에서 재생하는 운전 보조 기능(#300). 명령 실행과 기기 실측 표시는 분리한다.

## 운영 규칙

기준 프로파일에서 TP 이전·동일 시각에 기록한 조절은 투입 후 경과 시간으로, TP 이후 조절은 BT 도달로 재현한다. 분류에는 저장된 기준 TP(폴백 포함)를 우선 사용하고, 없는 구기록은 기준 BT 곡선에서 TP를 추출한다. 어느 쪽도 없으면 기존처럼 기록된 조절을 시간으로 재현한다. 기존에 명시적으로 저장한 시간/BT 조건은 그대로 사용한다.

새 조건은 BT 도달값과 화력만 추가할 수 있다. 각 행에서는 실제 실행 기준에 해당하는 값과 화력만 편집하며 기준을 바꿀 수 없다. BT 조건은 이번 배치의 실제 TP 확인 후에만 실행하고, 이번 배치의 폴백 TP만으로 실행하지 않는다. 조건은 목록 순서대로 실행하므로 앞 조건이 미충족이면 뒤 조건도 대기한다. 차트의 시간 좌표는 참고용이며 BT 조건의 예정 실행 시각을 뜻하지 않는다.

Replay의 현재 온도 조건은 표시용 EMA가 아닌 raw BT로 판정한다. 기존 프로파일에 저장된 목표 온도는 변경하지 않는다. raw 누락·stale·중복·이상치 표본에서는 시간/온도 이벤트 모두 보류하고 마지막 정상 관측의 나이를 유지한다. 기존 BT 필터(0–400°C 범위, 최대 15°C/s 변화율)를 사용하며, 큰 단일 스파이크는 보류하고 서로 다른 시각의 연속 표본이 급변을 확인하면 허용한다. 작은 유효 노이즈의 임계값 통과에는 별도 히스테리시스를 적용하지 않는다.

1. **재생 중 자리를 비우지 않는다.** 화력은 앱이 돌려도 안전 감시는 항상 로스터의 책임이다.
2. **수동 보정은 재생을 끈 뒤 한다.** 재생 중에는 앱 화력 슬라이더가 잠긴다. 기기 조작반·타 소프트웨어·본체 자동 제어의 변경을 실측 차이만으로 감지하거나 재생을 자동 중지하지 않는다. Replay를 켜 둔 채 본체에서 조작하면 다음 재현 명령이 그 설정을 바꿀 수 있다. 다시 켜면 현재까지 순서대로 충족된 마지막 조건의 화력을 적용하고 이후 조건을 기다린다.
3. **하루 첫 1–3배치는 주의 깊게 본다.** 기기 온도가 안정되기 전에는 레퍼런스와 거동이 달라 수동 보정이 필요할 수 있다.
4. **기센은 본체 Auto를 Manual로 둔다.** 본체 자동 제어와 병행하면 앱 지시가 덮인다.
5. **레퍼런스의 배출 이후 기록은 재생하지 않는다.** 컷오프는 레퍼런스 세션의 Drop 마크다(없으면 프로파일 duration). 배출 후 쿨다운 중 가스 조작은 이번 배치에 섞이지 않지만, 레퍼런스에 Drop 마크가 없으면 End 확정까지의 조작이 포함될 수 있으니 레퍼런스 배치는 Drop을 마킹한 세션으로 만든다.
6. **화력 0 명령은 실제 소화 확인이 아니다.** 클래식 기센(DB2 계열) 기본 맵은 논리 0–100에 1을 더해 세트포인트에 쓴다. 앱의 0은 PLC 원시값 1이며 원시값 0(AUTO)과 다르다. 버너가 꺼졌는지는 조작반에서 확인한다. W6A PRO는 다른 세트포인트 맵을 사용한다.
7. **배출 시 화력은 설정("배출 시 화력 처리")을 따른다.** PID와 공용 정책이다(#316). `화력 0으로`면 Drop 마크 즉시 0 명령을 보내고, 피드백이 따라오지 않으면 기존 10회 피드백 간격으로 다시 보낸다. 이 재시도 신호는 배출 후 0 명령에만 사용하며 일반 Replay를 중지하거나 미반영 경고로 표시하지 않는다. `현재 화력 유지`면 마지막 재생 값을 기기에 남긴다. 배출 취소·앱 수동 조작은 배출 후 재시도를 취소한다.

## 명령 전송과 피드백

일반 Replay는 요청한 논리 화력과 일치하는 응답을 받은 뒤 해당 조건을 소비한다. 클래식 Giesen DB2 기본 화력 맵은 전송 직후 같은 연결에서 DB2.14를 새로 읽어 쓴 값과 일치하는지 확인한 뒤 응답한다. 논리 0은 raw 1을 확인하며 raw 0(AUTO)은 불일치다. 쓰기 전 캐시나 실측 채널(DB2.48 등)을 설정값 확인에 사용하지 않는다. 이 검증은 해당 맵에만 적용하며 다른 장비·커스텀 맵의 전송 응답을 설정값 확인으로 간주하지 않는다.

전송·설정값 읽기 실패, 설정값 불일치, 요청과 다른 응답은 해당 단계를 대기 상태로 유지하고 500ms 뒤 재시도한다. 최초 전송을 포함해 최대 3회이며 그동안 다음 단계가 충족돼도 실패한 명령을 건너뛰지 않는다. Giesen DB2 검증 맵은 재시도 전에 설정 셀을 새로 읽는다. 이미 요청값이면 재전송 없이 완료하고, 불일치하면 같은 명령을 한 번 보내고 다시 확인한다. 읽기 자체가 실패하면 재전송하지 않고 다음 확인 기회를 기다린다. 확인 미지원 맵은 같은 논리 명령을 다시 전송한다. 연결 세대를 알 수 없으면 재시도하지 않는다.

3회 모두 실패하면 Replay를 중지하고 실패한 조건을 남긴다. 이후 사용자가 현재 화력을 확인한 뒤 명시적으로 재개한다. 재시도 대기·진행 중 앱 수동 조작·PID 개입·배출·배치 종료·프로파일 교체·연결 교체·관측 보류가 생기면 남은 재시도를 취소한다. sidecar도 연결 세대, 마지막 요청 화력, 도중의 새 화력 명령과 PID 제어권, 최대 2회 추가 시도를 검사한다. 이전 연결의 대기 명령을 새 PLC에 보내거나 늦은 응답으로 중단된 재생을 진행하지 않는다. 본체에서의 외부 조작을 이 앱의 제어권 변경처럼 모두 감지하는 것은 아니므로 기존 Manual 운전 규칙을 지킨다.

연결 세대 교체 자체로 Replay를 끄지 않는다. 자동 재연결 중에는 일반 명령을 보류하고, 복구 후 정상 관측으로 미처리 단계를 다시 판정한다. 마지막 정상 관측이 오래되어도 Replay는 켜 둔 채 보류만 하며, 복구 첫 유효 관측에서 따라잡는다. 이전 연결의 늦은 응답은 단계나 복구 후 진행 중인 명령을 변경하지 않는다.

설정값 확인은 그 시점의 PLC 저장값 확인이며 버너 동작 확인은 아니다. 실측 지연·정체·양자화·변조만으로 일반 Replay를 중지하거나 재전송하지 않는다. 화력 0 명령 뒤 새 실측 화력이 계속 양수인 경우에는 기존 5초 진단 경고를 유지한다. 입력값과 기기 실측 표시는 유지하고, 실측이 입력값에 수렴하면 슬라이더가 다시 기기값을 따른다. 확인 후 본체 설정이 바뀌는 경우까지 지속 감시하거나 자동 복원하지 않는다.
